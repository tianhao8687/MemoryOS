# DeepSeek V4 Flash × MemoryOS 插件 A/B/C 报告（medium-abc-v3-live-r1）

生成日期：2026-08-17（Asia/Shanghai）  
任务：`pylint-pr-4661`  
插件版本：`0.1.9`

## 结论

这轮没有证明 MemoryOS 提高了修复成功率。A、B、C 的最终补丁都为空，离线隐藏验收都失败。最准确的判断是：

- MemoryOS 的安装、完整上下文、渐进索引和按需解释调用链均正常。
- B（完整记忆）相对 A 显著减少了输出、推理和费用，但多用了输入与请求；这是单题效率信号，不是成功率证据。
- C（优化后的渐进记忆）把模型可见记忆载荷由 B 的 409 token 降到 287 token，但没有压住 Agent 的长推理；C 的总费用反而最高，并被 130% 费用保护器停止。
- 本轮失败的主因不是题目太难、插件调用失败或输入载荷过大，而是 Agent 已经知道正确契约和代码位置后，仍持续寻找上游实现、检查缺失依赖和尝试联网，没有进入编辑。

因此，**插件具备检索和定向价值，但当前版本还没有把“已解决的记忆契约”可靠转换为实现动作；尤其 C 的端到端成本效率本题不合格。**

## 实验控制

- A：`no_memory`，不暴露 MemoryOS 工具。
- B：`msc_full`，暴露完整 MemoryOS 上下文。
- C：`msc_progressive`，暴露优化后的紧凑索引和一次按需解释。
- 三组使用相同的 `deepseek-v4-flash`、`high` 推理等级、`standard-offline` Agent 预设、任务提示、基础提交和并行启动条件。
- 提示词 SHA-256：三组均为 `2a0f9dd9a436d41e3c47f291c0fb65422b06540925de71c147fff4817de4ccb8`。
- 起始状态 SHA-256：三组均为 `286a1573c5c3cd95475c724768d0596120371a1d1d53385fac7f7ff000c63421`。
- Provider 重试上限为 0；所有记录的 `attempt_index` 均为 1，没有自动重试、自动重复或自动扩容。
- 隐藏补丁和评分目录位于 Agent 根目录之外。
- 当另外两个方案结束后，仍在运行的方案若在输入 token、Provider 尝试或费用上超过同伴最大值的 130%，插件会在下一次 Provider 调用前停止。

## 本轮插件侧优化

本轮只修改 MemoryOS 插件，没有加入“第几步必须写代码”、DeepSeek 专用编辑期限或题目答案：

1. 渐进索引只保留相关记录、`resolved` 状态和精确的 `memory_explain` 入口。
2. 按需解释去重重复事实、证据和历史，保留仓库本地来源锚点，并移除 URL/Git 来源噪声。
3. 解释结果增加通用边界：相关条款作为一个契约，只检查命名符号或最近匹配代码一次；匹配后进入实现和测试。
4. 保留请求前 130% 用量保护器和隐藏评分隔离。

## 插件直接效果

### 调用链和载荷

- B 成功调用 `memory_context` 一次，模型可见记忆载荷为 409 token。
- C 成功调用 `memory_context` 和 `memory_explain` 各一次，总模型可见记忆载荷为 287 token，比 B 少 122 token（29.8%）。
- 首请求工具 schema 大小：A 27,063 bytes，B 27,258 bytes，C 27,631 bytes。C 相对 A 的固定接口增量为 568 bytes。
- 前 10 个完成响应的累计输入：A 176,052，C 176,861；C 仅高 809 token（0.46%）。这说明 C 的异常费用不是由记忆输入膨胀造成的。

### B 的方向性信号

B 相对 A：

- 推理 token 减少 37.7%；
- 输出 token 减少 37.1%；
- 费用减少 23.0%；
- 但输入 token 增加 10.7%，Provider 尝试多 2 次；
- 最终仍未编辑，功能收益为 0。

这支持“完整记忆降低了本题部分调查/推理成本”的弱结论，但单题且无成功补丁，不能据此宣称插件普遍有效。

## 为什么推理输出突然变多

长推理不是 C 独有，在三个方案中都出现：

| 方案 | 最大推理峰值 |
|---|---|
| A | step 4 = 7,626；step 11 = 4,092；step 7 = 1,841 |
| B | step 6 = 5,130；step 7 = 2,299；step 11 = 576 |
| C | step 6 = 7,973；step 10 = 6,927；step 7 = 4,912 |

C 的三个峰值合计 19,812 token，占 C 全部推理 token 的 98.6%。轨迹显示：

1. 三组都在 step 3 左右读到 `pylint/config/__init__.py` 和现有 `PYLINTHOME` 分支。
2. B 在 step 1 已收到完整契约；C 在 step 2 已收到精简契约，明确说明缓存目录、环境变量优先级、无 home 回退和旧目录兼容。
3. 之后三个 Agent 都转向猜测历史 PR、检查 `platformdirs`、尝试下载上游 Pylint 或检查网络/依赖，而不是修改文件。
4. C 的 step 6 产生 7,973 推理 token，下一请求输入从 12,661 跳到 21,389；step 7 又产生 4,912 推理 token，后续输入升到 29,850。也就是说，大段推理被继续带入会话，形成输入增长反馈。

参考提交的任务核心实际很小：使用 `appdirs.user_cache_dir("pylint")`（隐藏验收也接受 `platformdirs` 或直接 XDG 实现）、声明运行时依赖、保留 `PYLINTHOME`/无 home 行为并提示旧目录。缺少本地依赖并不妨碍先修改代码或运行静态检查。Agent 将“不能安装依赖”误判为“不能实现”，才是未写补丁的直接原因。

因此，之前的突发推理不能只归因于 MemoryOS。更准确的解释是：DeepSeek V4 Flash 在缺少可运行依赖时容易进入“寻找参考实现—验证环境—重新规划”的长推理模式；C 的记忆没有制造这个模式，但当前通用边界也没有阻止它。

## 130% 保护器结果

A 和 B 结束后，C 已完成 10 个响应：

- C 费用：USD 0.0085606360
- 同伴最高费用（A）：USD 0.0059651312
- 130% 上限：USD 0.00775467056

保护器以 `relative_overuse:cost_usd` 触发。C 没有记录第 11 次 Provider 尝试，说明本轮请求前阻断生效，且没有在途超调。

## A 的“外部阻断”说明

A 的框架状态是 `external_blocker`，但不是 API、仓库或隐藏评分基础设施故障。Agent 的最后输出认为本地缺少测试依赖且无网络，因此继续调查；随后无补丁预算到达上限。A 的补丁为空。

为统一验收口径，控制器在隔离目录中对 A 的空补丁补做了相同隐藏测试，结果同样失败：`default PYLINT_HOME is not derived from a platform-aware user cache`。因此三组功能结果都应记为失败。

## 无效启动与全部 API 用量

首次正式启动前有两类基础设施事件：

1. 三个容器因 `/host_mnt/d/...` 路径未挂载而在控制器初始化阶段退出，Provider 请求为 0。
2. 修正路径后，A/C 的并行仓库克隆达到 180 秒上限；B 已先进入 Agent 阶段。发现偏斜后立即停止 B，但停止前产生 8 次 Provider 尝试、7 个完成响应、87,276 输入 token、7,402 输出 token、6,546 推理 token，费用 USD 0.0033678848。该运行已归档，完全排除在 A/B/C 结论之外。

包含这次无效启动，本次操作总计：44 次 Provider 尝试、41 个完成响应、688,843 输入 token、54,508 输出 token、49,356 推理 token、费用 USD 0.0224873320。没有重试。

## 验收边界

- 已证明：插件 0.1.9 可安装；B/C 工具被真实调用；渐进载荷更小；隐藏评分隔离有效；130% 请求前停止有效。
- 有弱信号：B 在本题的推理、输出和费用低于 A。
- 未证明：修复成功率提高、总输入稳定下降、跨题泛化、C 优于 B。
- 本轮否定：C 的端到端成本效率合格；插件能可靠推动 Agent 从正确诊断进入编辑。

下一步若继续优化，应仍在插件侧做通用改进：当记忆状态为 `resolved` 且本地代码已匹配契约时，明确把“外部参考不可用/依赖未安装”降级为验证限制，要求先实现并使用可用的静态或最小检查。它不应规定固定步数，也不应写入 Pylint、DeepSeek 或某个依赖名。该方向尚未在本轮后实现或测试。
